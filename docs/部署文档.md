# 外卖系统 · 单机 Docker 部署文档

本文档描述如何从 **WSL2（控制节点）** 用 Ansible 把外卖系统部署到 **一台 Linux 虚拟机（目标机）**，
并在同一台机器上用 Nginx 做**双后端负载均衡 + 故障自动剔除**，用 MinIO 提供**对象存储**。

---

## 一、架构总览

```
┌─────────────────────────────────────────────────────────────────────┐
│  目标机（1 台 Linux，Docker Compose 编排全部服务）                    │
│                                                                     │
│   ┌────────────┐   :80 / :81 对外                                   │
│   │  Nginx     │  upstream takeout_backend {                         │
│   │  1.27      │     server backend-1:8080 max_fails=2 fail_timeout=10s │
│   │            │     server backend-2:8080 max_fails=2 fail_timeout=10s │
│   │            │  }                                                  │
│   └─────┬──────┘      ↓ 轮询 / ip_hash / weight / least_conn          │
│         │                                                           │
│         ├────────────────┬────────────────┐                         │
│         ▼                ▼                │                         │
│   ┌──────────┐     ┌──────────┐           │                         │
│   │backend-1 │     │backend-2 │           │                         │
│   │ :8080    │     │ :8080    │           │                         │
│   │ CACHE=redis   │ CACHE=redis           │                         │
│   │ 文件→MinIO     │ 文件→MinIO            │                         │
│   └────┬─────┘     └────┬─────┘           │                         │
│        └───────┬────────┘                 │                         │
│                ▼                          │                         │
│      ┌──────────────┐   ┌──────────────┐  │                         │
│      │  Redis 7.2   │   │  MySQL 8.0.36 │  │                         │
│      └──────────────┘   └──────────────┘  │                         │
│                                            │                        │
│      ┌────────────────────────────────┐    │                        │
│      │  MinIO（S3 兼容对象存储）        │◀───┘ /files/ 反代取图       │
│      │  桶 takeout        商品图/头像   │                            │
│      │  桶 takeout-backup 数据库备份    │                            │
│      └────────────────────────────────┘                            │
└─────────────────────────────────────────────────────────────────────┘
```

**对外只暴露 80（顾客端 H5）和 81（商家/管理端 Admin）**，
其余端口（8080/3306/6379/9000）只在 Docker 网络内部或宿主机 127.0.0.1 上，不对局域网开放。

### 单机为什么也必须解决"共享"

两个后端是同一镜像的两个实例，但它们**不共享 JVM 内存**：

| 状态                                  | 单机多实例的坑                   | 解决方式                  |
| ------------------------------------- | -------------------------------- | ------------------------- |
| JWT 黑名单 / refresh token / 限流计数 | A 实例登出，B 实例还认这个 token | `CACHE_TYPE=redis`        |
| 商品图片 / 用户头像                   | 上传到 A 实例，B 实例读不到      | `FILE_STORAGE_TYPE=minio` |
| 业务数据                              | ——                               | MySQL 天然共享            |

两个切换都通过接口抽象（`CacheClient` / `FileStorageService`）完成，**业务代码零改动**。

## 四、前置条件

**控制节点（WSL2）**

- 已安装 Docker（构建镜像用）——`docker version` 能跑通
- 已安装 Ansible（`ansible-playbook --version`）
- 能免密 SSH 到目标机

**目标机（1 台虚拟机）**

- RHEL 系发行版：**Rocky / CentOS / AlmaLinux 9**（docker 与 zabbix 仓库地址按此写）
- 建议 ≥ 2 核 4G，磁盘 ≥ 20G
- root 可 SSH 登录

**其他**

- 一台 Zabbix Server（可复用你博客项目那台），或先把 `zabbix_server_ip` 留占位

## 五、部署步骤

### 第 0 步：项目放到 WSL2

```bash
# 建议放 ASCII 路径，避免中文路径在 Docker 构建上下文里出问题
mkdir -p /opt && cp -r "/mnt/c/Users/huhaohua/Desktop/myproject/外卖系统" /opt/takeout-src
cd /opt/takeout-src/deploy/ansible
```

### 第 1 步：配置主机清单

```bash
cp inventory.ini.example inventory.ini
vi inventory.ini     # 把 <目标机IP> 换成真实 IP，私钥路径改成你自己的
```

### 第 2 步：填写变量

```bash
# 密钥文件：先复制模板（vault.yml 已被 .gitignore 排除，不会误提交）
cp group_vars/all/vault.yml.example group_vars/all/vault.yml
vi group_vars/all/vault.yml   # 填真实密码：MySQL / Redis / MinIO / JWT

# 非敏感变量：按需调整
vi group_vars/all/main.yml    # 重点改：zabbix_server_ip、minio_console_bind、（可选）镜像版本
```

生成随机密钥可用：`openssl rand -base64 32`

### 第 3 步：加密敏感变量（推荐）

```bash
ansible-vault encrypt group_vars/all/vault.yml
# 之后每次跑 playbook 都要带 --ask-vault-pass
```

### 第 4 步：安装 Ansible 集合

```bash
ansible-galaxy collection install -r requirements.yml
```

### 第 5 步：执行部署

```bash
ansible-playbook site.yml                  # 未加密 vault
ansible-playbook site.yml --ask-vault-pass # 已加密 vault
```

playbook 按以下顺序执行：

1. **前置检查**（目标机）：发行版校验、80/81 端口占用检查
2. **构建镜像**（控制节点）：`docker build` 后端与网关，`docker save` 成 tar
3. **部署**（目标机）：
   - `docker` role：装 Docker、配镜像加速、**容器日志轮转**、预拉基础镜像
   - `journald` role：**主机日志**容量上限 + 落盘
   - `firewall` role：放行 80 / 81
   - `takeout-init` role：传 compose、渲染 `.env`、传 tar 并 `docker load`、`docker compose up -d`、等待网关就绪
   - `takeout-backup` role：下发备份脚本 + systemd 定时器 + 心跳文件
   - `zabbix-agent` role：装 Agent2 + 自定义监控项 + 放行 10050

部署完成会打印容器状态与网关就绪信息。

## 六、关键设计说明（面试可讲）

### 6.1 Nginx 负载均衡与故障自动剔除

`deploy/nginx/nginx.conf`：

```nginx
upstream takeout_backend {
    server backend-1:8080 max_fails=2 fail_timeout=10s;
    server backend-2:8080 max_fails=2 fail_timeout=10s;
    keepalive 32;
}
```

- **`max_fails=2 fail_timeout=10s`**：连续 2 次连接失败 → 标记该节点 down → 10 秒内不再转发；
  10 秒后试探，恢复则自动放回。这就是"一个挂了另一个接着服务"。
- 换调度策略只需在 upstream 里加一行（文件里注释了模板）：
  - `ip_hash;` —— 会话粘滞，同一客户端固定落到同一实例
  - `least_conn;` —— 最少连接优先
  - `server backend-1:8080 weight=7;` —— 权重分流（7:3）

### 6.2 为什么端口隔离而不是 `/admin/` 子路径

admin 工程内部路由自带 `/admin` 段（管理后台）。若把它挂在 `/admin/` 子路径下，
会出现 `/admin/admin/xxx` 这种丑 URL，还要改 vite base + router base。
用 **80 顾客端 / 81 管理端** 端口隔离，**零前端改动**且 URL 干净。

### 6.3 为什么数据层用 named volume 而不是 bind mount

bind mount 到宿主目录会在 SELinux enforcing 的 RHEL 上遇到标签问题、以及在权限上踩坑。
named volume 由 Docker 管理，**完全绕开这些**；备份走 `mysqldump` 导出，不依赖宿主路径。

> 注意：`docker compose down -v` 会连同数据卷一起删除。

### 6.4 备份：本地 + MinIO 双份

`takeout-backup` 每天 3 点执行：

```
mysqldump --single-transaction → gzip → 本地 /opt/takeout/backup/（保留 7 天）
                                        ↓ gzip -dc | rclone rcat
                                   MinIO 桶 takeout-backup（云端副本）
```

- rclone 用**环境变量配置**（不挂配置文件），规避 SELinux 与权限问题
- 上传失败只告警、**不删本地备份** —— 本地那份始终可回滚
- 成功后写 `/opt/takeout/status/last_success`（心跳，给 Zabbix 判断备份是否静默失败）

### 6.5 两套日志各管各的

| 日志     | 看它的命令    | 归谁管                                                        |
| -------- | ------------- | ------------------------------------------------------------- |
| 容器日志 | `docker logs` | `docker` role 的 `daemon.json`（json-file 驱动，10m × 3）     |
| 主机日志 | `journalctl`  | `journald` role（`SystemMaxUse=200M` + `Storage=persistent`） |

两套存储互不相通，改配置前先想清楚改哪一套。

## 七、日常运维命令

```bash
cd /opt/takeout

# 查看状态 / 日志
docker compose --env-file .env ps
docker compose --env-file .env logs -f --tail=100
docker logs -f takeout-backend-1

# 重启单个服务
docker compose --env-file .env restart backend-1

# 验证负载均衡（连打 10 次，看落到哪个实例）
for i in $(seq 10); do curl -s -o /dev/null -w "%{http_code}\n" http://<目标机IP>/nginx-health; done
docker logs takeout-backend-1 --tail=5
docker logs takeout-backend-2 --tail=5

# 手动跑一次备份
/opt/takeout/backup/backup-db.sh

# 查看备份定时器
systemctl list-timers takeout-backup.timer
```

### 更新代码后重新发布

```bash
cd /opt/takeout-src/deploy/ansible
ansible-playbook site.yml --ask-vault-pass     # rebuild_images 默认 true，会重新构建并滚动更新
```

### 回滚

镜像按版本 tag 管理。回滚就是改回旧版本号再跑一次：

```bash
# 1) 改 group_vars/all/main.yml 的 app_version 为旧版本
# 2) 但旧版本镜像需要重新构建 —— 更快的做法是直接切镜像 tag：
cd /opt/takeout
docker compose --env-file .env down
# 把 .env 里 APP_VERSION 改成旧版本（前提是该版本镜像还在 docker images 里）
docker compose --env-file .env up -d
```

## 八、常见问题

**Q：拉镜像很慢或超时？**
`docker` role 的 `daemon.json` 已配置国内镜像加速器（`group_vars` 里可增删）。
若目标机完全无法访问外网，需要先把基础镜像导出成 tar 手工 load。

**Q：目标机不是 Rocky/CentOS 9？**
`site.yml` 里有一条断言会明确报错。用 Ubuntu 的话需要改 `roles/docker` 的仓库地址
（`https://download.docker.com/linux/ubuntu`）与 `roles/zabbix-agent` 的仓库包（ubuntu 版）。

**Q：Zabbix Server 连不上 10050？**
目标机若在 NAT 后方没有入方向端口，参考博客项目的做法：
用反向 SSH 隧道把目标机 10050 映射到 Server 上，再用 systemd 托管实现自愈。
此时 `zabbix_server_ip` 填隧道对端的地址。

**Q：`docker compose down -v` 后数据没了？**
`-v` 会删除 named volume。日常重启请用 `restart` 或 `up -d`，不要加 `-v`。

**Q：想改 Nginx 负载均衡策略？**
改 `deploy/nginx/nginx.conf` 的 upstream（注释里有 ip_hash / least_conn / weight 模板），
然后重新构建网关镜像并发布：
`ansible-playbook site.yml --ask-vault-pass`
